### تمرین عملی (روی یک کار واقعی)

**مثال واقعی:** در پروژه `mysite` که اپلیکیشن «فروشگاه کتاب» را دارد، می‌خواهیم DRF را نصب و راه‌اندازی کنیم و اولین API قابل‌مرور برای کتاب‌ها را بسازیم. هدف این است که با تنظیمات پایه آشنا شویم و ببینیم DRF چطور داده را نمایش می‌دهد و دریافت می‌کند.

**تیتر کارها و توضیح هر کدام در این مثال:**

1. **فعال‌سازی محیط مجازی**  
   قبل از نصب هر بسته، محیط مجازی پروژه را فعال کنید تا وابستگی‌ها از سیستم جدا بمانند. خودتان دستور فعال‌سازی را بر اساس سیستم‌عامل‌تان بنویسید و بعد با `pip --version` مطمئن شوید داخل محیط مجازی هستید.

2. **بررسی نسخه‌ی پایتون**  
   DRF به پایتون ۳.۸ یا بالاتر نیاز دارد. نسخه‌ی پایتون خود را چک کنید و اگر قدیمی بود ارتقا دهید. این کار از بروز خطاهای عجیب هنگام اجرا جلوگیری می‌کند.

3. **نصب بسته‌ی DRF**  
   با pip بسته‌ی `djangorestframework` را نصب کنید. توصیه می‌شود `markdown` را هم نصب کنید تا Browsable API (رابط گرافیکی مرورگر) درست نمایش داده شود. دستور نصب را خودتان بنویسید و اجرا کنید.

4. **تأیید نصب**  
   با `pip list` یا `pip show` بررسی کنید که DRF نصب شده و نسخه‌اش چیست. نسخه را یادداشت کنید چون در مستندات بعضی امکانات به نسخه وابسته‌اند.

5. **افزودن `rest_framework` به `INSTALLED_APPS`**  
   فایل `settings.py` را باز کنید و `'rest_framework'` را به `INSTALLED_APPS` اضافه کنید. بدون این کار Django از وجود DRF باخبر نمی‌شود و تنظیماتش اعمال نمی‌شود. سعی کنید این یک خط را خودتان اضافه کنید.

6. **افزودن دیکشنری `REST_FRAMEWORK` در settings**  
   یک دیکشنری به نام `REST_FRAMEWORK` در `settings.py` بسازید. اینجا تنظیمات سراسری DRF می‌نشیند. فعلاً فقط یک تنظیم ساده (مثل مجوز پیش‌فرض `AllowAny`) بگذارید تا API برای تست باز باشد؛ بعداً سخت‌گیرانه‌اش می‌کنیم.

7. **تنظیم `DEFAULT_RENDERER_CLASSES`**  
   Renderer مشخص می‌کند پاسخ API به چه شکلی به کلاینت برود. `JSONRenderer` خروجی خام JSON می‌دهد (برای اپ موبایل و فرانت‌اند) و `BrowsableAPIRenderer` یک صفحه‌ی HTML تعاملی برای مرورگر می‌سازد. هر دو را در لیست بگذارید.

8. **تنظیم `DEFAULT_PARSER_CLASSES`**  
   Parser مشخص می‌کند DRF چه فرمت‌های ورودی را می‌فهمد. `JSONParser` برای بدنه‌ی JSON، و `FormParser` و `MultiPartParser` برای فرم‌های HTML و آپلود فایل. برای شروع JSON کافی است اما آپلود فایل بعداً به بقیه نیاز دارد.

9. **ساخت مدل Book برای داده‌ی واقعی**  
   اگر هنوز مدلی برای کتاب ندارید، یک مدل ساده با فیلدهای `title`، `author` و `price` بسازید. سپس `makemigrations` و `migrate` را اجرا کنید. کد مدل را خودتان بنویسید؛ هدف این است که API روی داده‌ی واقعی کار کند، نه دیکشنری خالی.

10. **ساخت اولین Serializer**  
    یک فایل `serializers.py` بسازید و یک `BookSerializer` بنویسید که از `ModelSerializer` ارث‌بری کند و در `Meta` مدل و فیلدها را مشخص کند. Serializer کار تبدیل مدل به JSON و برعکس را انجام می‌دهد. جزئیات کامل در سرفصل «Serializers» می‌آید.

11. **ساخت اولین API View با `@api_view`**  
    در `views.py` یک تابع بنویسید که با دکوراتور `@api_view(['GET'])` تزئین شده باشد، همه‌ی کتاب‌ها را بگیرد، با Serializer سریالایز کند و با `Response` برگرداند. کد را خودتان بنویسید و در صورت گیر کردن به مستندات Tutorial 1 مراجعه کنید.

12. **تعریف URL برای API**  
    یک `urls.py` داخل اپ بسازید و مسیر `books/` را به ویو وصل کنید، سپس آن را در `urls.py` اصلی پروژه با `include` زیر پیشوند `api/` قرار دهید. حالا آدرس API شما چیزی مثل `/api/books/` می‌شود.

13. **اجرای سرور و مشاهده‌ی Browsable API**  
    سرور را اجرا کنید و آدرس `/api/books/` را در مرورگر باز کنید. اگر Renderer درست تنظیم شده باشد، یک صفحه‌ی HTML با لیست کتاب‌ها و یک فرم برای POST می‌بینید. این همان BrowsableAPIRenderer است.

14. **تست GET با ابزار خط فرمان**  
    با `httpie` یا `curl` یک درخواست GET به API بزنید و خروجی JSON را ببینید. این همان داده‌ای است که اپ موبایل یا فرانت‌اند دریافت می‌کند. ابزار را خودتان انتخاب و نصب کنید.

15. **تست POST برای ایجاد کتاب جدید**  
    با همان ابزار، یک درخواست POST با بدنه‌ی JSON بفرستید و ببینید کتاب جدید با کد وضعیت ۲۰۱ ساخته می‌شود. توجه کنید که DRF داده را با Serializer اعتبارسنجی می‌کند؛ اگر فیلد اجباری نباشد، خطای ۴۰۰ می‌گیرید.

16. **تست خطای اعتبارسنجی**  
    یک POST با داده‌ی ناقص (مثلاً بدون `title`) بفرستید و ساختار پاسخ خطا را ببینید. این ساختار JSON دقیقاً چیزی است که در فصل «Validation Errors» کامل بررسی می‌شود.

17. **ساخت Router و ثبت ViewSet (پیش‌نمایش)**  
    بعد از اینکه با ViewSet آشنا شدید، می‌توانید یک `DefaultRouter` بسازید و ViewSet را با `register` ثبت کنید تا همه‌ی URLها خودکار ساخته شوند. الان فقط بدانید این امکان وجود دارد؛ جزئیات در سرفصل «ViewSets and Routers» است.

18. **غیرفعال‌کردن موقت Browsable API**  
    اگر می‌خواهید ببینید پاسخ خام JSON چه شکلی است، موقتاً `BrowsableAPIRenderer` را از لیست Rendererها بردارید و دوباره تست کنید. سپس برگردانید تا تجربه‌ی توسعه راحت بماند.

19. **بررسی صفحه‌ی ریشه‌ی API**  
    اگر از DefaultRouter استفاده کنید، آدرس `/api/` یک صفحه‌ی ریشه نشان می‌دهد که فهرست همه‌ی endpointها را با لینک دارد. این صفحه به کشف API کمک زیادی می‌کند.

20. **تمرین تکمیلی: مستندسازی خودکار API**  
    کتابخانه‌ی `drf-spectacular` را نصب کنید، به `INSTALLED_APPS` اضافه کنید و `DEFAULT_SCHEMA_CLASS` را در تنظیمات DRF ست کنید. سپس مسیر مستندات Swagger را اضافه کنید و ببینید DRF چطور مستندات API شما را خودکار می‌سازد.
